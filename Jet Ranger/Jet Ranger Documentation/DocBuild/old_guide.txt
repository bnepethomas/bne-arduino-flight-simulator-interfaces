
Jet Ranger Cockpit – User Guide
Oct 11, 2026 · @Peter
Overview
The Jet Ranger cockpit drives real gauge needles, warning lights, radio displays and switches from the simulator. A Windows PC exchanges UDP packets over Ethernet with five Arduino Mega 2560 panel boards, and a small USB board presents the panel switches to Windows as joysticks.

Data flows one way, PC to board. On the primary PC, a Python listener shows the board's debug messages and a separate Windows app, the Health Monitor, tracks its keep-alives. Cockpit switches reach the simulator separately, as FSUIPC events.

Windows and simulator
The Windows PC runs the simulator and a bridge program that turns simulator variables into UDP text packets for the Arduino. Switch inputs travel the other way as simulator events.
The FSUIPC bridge sends the Servo, Stepper and Dual Stepper boards each their own packet in real units (degrees, knots, feet per minute, psi, percent, degrees C), and the boards convert them with their own calibration. It sends about 10 packets per second to each board; the radio gets a packet whenever a frequency changes and at least every 5 s. The Dual Stepper's temperature OLED shows the outside air temperature from the simulator.
MSFSWinformsAutoCS is the Microsoft Flight Simulator 2020 / 2024 version of the same bridge: it reads the values through SimConnect and sends the same packets to the same boards, so the panel behaves the same with either. Run only one bridge at a time, because both listen for the radio board's commands on UDP 27001. It has been run against MSFS 2024 with the FlyInside B206.

The bridge sends real units: degrees for the attitude indicator, and knots, ft/min, °C, psi, % or US gallons for the gauges. Each board turns them into a servo position or stepper steps with calibration tables in its own sketch.
Running the MSFS bridge
1. Build the project MSFSWinformsAutoCS (in the repo's C# Code folder) and run MSFSWinformsAutoCS.exe from its bin\Debug folder. Build output is not stored in git, so a fresh copy of the repo has to be built first.
2. Close the FSUIPC bridge if it is running, then start MSFS and load a Jet Ranger. The order does not matter: the bridge keeps looking for the simulator. The status bar changes from Disconnected (red) to Connected to MSFS with the aircraft name (green) once data arrives.
3. The window lists the values being sent and the warning lamps. The Avionics Master box follows the simulator and can also be used to switch it.
4. If the status turns orange and says no data, the simulator is paused or loading and the bridge has stopped sending; the boards return their gauges to zero after 30 s and carry on when data returns.
5. Five lamps are driven: engine out, rotor low, low fuel, generator fail (engine speed below 10 %) and transmission oil pressure (below 40 psi, using the estimated pressure on the FlyInside and CowaSim). The other lamps need aircraft-specific variables. Some MSFS Jet Rangers do not report every value (for example transmission pressure and temperature), so those gauges may stay at zero.
6. The FlyInside B206 does not give MSFS the values its own cockpit gauges show: its rotor speed, engine speed, gas producer, torque, turbine out temperature, fuel pressure and transmission oil are not in the standard simulator variables. For this aircraft the bridge reads the aircraft's own rotor and engine speed variables and estimates the rest from cockpit dial readings: torque follows the collective lever, turbine out temperature rises with torque, and the transmission oil pressure and temperature are modelled (the temperature warms up slowly from the outside air temperature and starts again from cold each time the bridge restarts). These are estimates and may be a few percent off at power settings that were not checked, so compare the panel gauges with the cockpit dials. Other aircraft use the standard variables.
7. In the FlyInside B206, holding full collective for more than about 2 seconds over-torques the engine and breaks it; the cockpit torque dial swings to about 115 %.
8. The status bar shows the name of the aircraft the simulator reports and follows it when you load a different one. The CowaSim Jet Ranger (shown as 206B3 with its registration, for example 206B3 C-GTOK) reports the standard variables and most of its gauges match, but its torque, turbine out temperature and electrical load dials do not read them, and it has no transmission oil values. For this aircraft the bridge smooths the torque, takes the turbine out temperature from the exhaust gas temperature, rescales the load and estimates the transmission oil from the rotor speed and the engine oil temperature. These were fitted to a few dial readings and may be a few percent off, so compare the panel gauges with the cockpit dials.
9. The electrical load follows the size of the total load whichever way the current flows, so with the engine stopped (battery supplying the bus) it still shows a load. The cockpit load dial of the FlyInside B206 does not move with it and stays at about 50 %.
Installing the DodoSim event file (FSUIPC)
Copy DODSIM206V2.EVT into the {P3D or FSX}/Modules folder, next to FSUIPC.ini.Add this to FSUIPC.ini if FSUIPC has not added it itself:
[EventFiles]
0=DodoSim206
Restart the simulator. The DS206.* events now appear in FSUIPC's button and key assignment lists.Bind each physical switch to its event. After an EVT update, FSUIPC re-indexes events alphabetically, so check and re-map bindings.

Packet format
UDP packet format · data and control
UDP packet format · data and control
A packet can carry any number of pairs, in any order, up to 1000 bytes. Unknown tokens are ignored, so the PC can send only the values that changed. For example, D,PITCH:5,BANK:-10,LOWF:0 sent to the servo board sets the attitude indicator to 5° pitch and −10° bank and turns off Low Fuel.
To test without the simulator, send a packet from a PC on the subnet, for example with PowerShell:
$u = New-Object System.Net.Sockets.UdpClient
$b = [Text.Encoding]::ASCII.GetBytes('D,PITCH:5,RLOW:1')
$u.Send($b, $b.Length, '172.16.1.102', 13136)
Arduino servo controller
The servo board is an Arduino Mega 2560 with an Ethernet module, on the Jet Ranger Front Panel Servo PCB at 172.16.1.102. It drives the attitude indicator's two servos, switches the 15 caution and warning annunciators and reads three front-panel switches. It runs JET_RANGER_SERVO_CONTROLLER.ino.
The other gauges that were once servo-driven (airspeed, VSI, torque, temperatures, pressures, fuel and RPM) now run on the two stepper boards.
Uploading the firmware
Open the sketch in the Arduino IDE and select Board: Arduino Mega or Mega 2560.Install the libraries it uses: Ethernet (with SPI), Servo, Ewma (jonnieZG) and DCS-BIOS.Upload, then watch the start-up self-test (below): both servos sweep and all 15 lamps light.

What happens at power-up
All 15 annunciators switch on as a lamp test.The Ethernet module is reset and starts at 172.16.1.102; the red LED flashes for 3 s.Ethernet Started goes to the Python debug listener.Pitch, then bank, sweeps from minimum to maximum and back (about 2 s each) and parks at its calibrated level position.All annunciators switch off.The starting state of the three front-panel switches is sent to the USB HID board, Setup Complete is logged and the 30 s no-data watchdog starts.
Normal running
Every 5 ms the board checks UDP 13136 and stores each value as a new target.Every 5 ms each servo steps one position towards its target, so the attitude indicator moves smoothly.A servo that has not moved for 1 s is detached to stop buzz; the next movement re-attaches it.Annunciators change as soon as a 0 or 1 arrives.Each front-panel switch change is debounced for 30 ms and sent to the USB HID board at 172.16.1.11:4210 as index,state (1 = closed).Every 10 s the board sends SERVO to the Health Monitor on UDP 13137.If no packet arrives for 30 s, both servos return to level and every annunciator goes out; the next packet brings them back.C,SWINGPITCH:1 or C,SWINGBANK:1 re-runs one sweep on demand. The board pauses for about 2 s while it runs.
Stepper controller (13 Stepper board)
A second Arduino Mega 2560, on the Jet Ranger 13 Stepper PCB at 172.16.1.105, drives 11 X27-style stepper gauges directly from its pins. Unlike the servo board, it takes real units (knots, fpm, °C, psi, %, US gallons) and converts them to needle steps with calibration tables in the sketch JET_RANGER_STEPPER_CONTROLLER.ino.

Behaviour
Power-up: status LEDs flash, Ethernet starts, backlighting ramps up, then each gauge does a self-test sweep in turn: fuel, torque, ITT, N1, VSI, IAS, radar altitude. Each sweep has its own on/off switch (SwingFA, SwingTQ and so on) near the top of the sketch.Running: every 5 ms the board checks UDP 13136 and moves each needle towards its target with smooth acceleration.No-data watchdog: if no packet arrives for 30 s, every needle returns to its zero.Zero trims: each gauge has a …ZeroOffset value to nudge its true zero without touching the calibration table.Keep-alive: sends STEPPER to the Health Monitor on UDP 13137 every 10 s; debug goes to the Python listener on UDP 27000.

Behaviour
Power-up: OLEDs start first, then each gauge sweeps in turn: engine oil pressure, engine oil temp, transmission pressure, transmission temp, electrical load, fuel load, engine RPM, rotor RPM, altimeter. The altimeter seeks its zero sensor before sweeping. Start-up takes about 65 s.No-data watchdog: after 30 s without a packet, needles return to zero and all OLEDs blank.On-demand sweeps: C,SWINGOILP:1, SWINGOILT, SWINGXMSNP, SWINGXMSNT, SWINGELECTRICALLOAD, SWINGFUELLOAD, SWINGRPME, SWINGRPMR, SWINGALT. Each blocks the board for 5–7 s.Fuel load and electrical load now sweep with the same 315-step range and homing as the engine and transmission oil gauges (they used 630 steps before), so their sweeps should be shorter; they have not been re-timed yet.Keep-alive: sends DUAL_STEPPER to the Health Monitor every 10 s, so it shows separately from the 13 Stepper board.
Known issues
RAM use is 75%; avoid adding more OLEDs or string-heavy code.The latest bench I2C scan found OLEDs on mux channels 1 to 4 (the clock and temperature displays answer); check by eye that each shows its text.Engine and rotor RPM tables assume 0% = 0 steps; RSoffset is not yet measured.The altimeter zero seek travels up to 10,080 steps, about 14 turns, before giving up.

Commands to the PC (UDP 27001)
Turning a knob changes the standby frequency on the OLED and sends the new value to the PC. Buttons in the first column of the matrix send these commands; other buttons are only logged to the debug listener.
Button (row, col 0)Command sentRow 0NAV1_RADIO_SWAP (NAV1 FREQ switch)Row 1NAV2_RADIO_SWAP (NAV2 FREQ switch)Row 2COM1_RADIO_SWAP (COMM1 Freq switch)Row 3COM2_RADIO_SWAP (COMM2 FREQ switch), then AVIONICS_MASTER_SET
The PC bridge (P3D_to_UDP, SimConnect_to_UDP or MSFSSimConnectExtractor, depending on the simulator) listens on 27001 and turns these into simulator events. The radio board sends COMM_NAV to the Health Monitor every 10 s; the Health Monitor turns its Comm/Nav light from green to orange, then red, when nothing arrives for 15–30 s.
The four swap switches are on the Jet Ranger COM and NAV board and share matrix column 0. NAV1 and NAV2 also swap their active and standby frequencies on the NAV OLED straight away, because the PC does not send NAV frequencies back; the COM swaps change the display only when the simulator returns the swapped frequencies. The FSUIPC bridge (FSUIPCWinformsAutoCS) handles NAV1_RADIO_SWAP and NAV2_RADIO_SWAP; the SimConnect and P3D bridges do not yet.
If no data packet arrives from the PC for 30 s and no knob or button is used, both OLEDs blank (as if the radio had no power). Turning a knob or pressing a button, or new data from the PC, switches them back on, and they blank again after another 30 s of silence. At power-up the matrix is ignored for the first 1.5 s so a floating input cannot send false button presses.
The displays also follow the aircraft's electrics: when the avionics bus is below 24 V the bridge tells the radio the power is off (NAVCOM1:0) and the COM and NAV displays go blank together; they light together again when the bus rises.
Each knob sends its standby frequency to the PC with the radio's name: COM1 as the bare number (for example 118.295), the others as COM2_STANDBY:118.295, NAV1_STANDBY:108.000 or NAV2_STANDBY:108.000. The FSUIPC bridge (FSUIPCWinformsAutoCS) tunes the matching radio. Nothing is sent during the first 1.5 s after power-up, so the knobs' start positions do not change the simulator. Each OLED line always shows two frequencies in a fixed 16-column layout (for example 128.300  127.800); the radio pads short values from the PC such as 127.80 so that COM2 and NAV2 never slide under the faceplate.
Tuning steps follow the standard channel spacing. The COM knobs run 118.000 to 136.975 MHz in 25 kHz channels (the major knob picks 118 to 136, the minor knob 000, 025, 050 and 075 after each MHz). The NAV knobs run 108.00 to 117.95 MHz in 50 kHz steps (major 108 to 117, minor 000, 050, 100 and so on). Each minor knob wraps round at the ends. 8.33 kHz channels are not offered. FSUIPC holds COM frequencies to 10 kHz, so in the simulator a channel such as 118.025 may appear as 118.02 or 118.03.
Known issues
Only COM1 and COM2 frequencies arrive from the PC; there are no NAV frequency tokens yet, although the NAV knobs are read.With the SimConnect, P3D and MSFS bridges, turning a COM2, NAV1 or NAV2 knob does not tune that radio: those bridges only understand the bare COM1 standby number, and the radio now sends COM2_STANDBY:, NAV1_STANDBY: and NAV2_STANDBY: for the other three. Use the FSUIPC bridge for full radio control.If every button in the matrix's first column stops working, send C,MATRIX:1 to port 13136: the radio prints the raw H/L state of each column to the debug listener. A column that reads L with nothing pressed is a hardware fault on that Mega pin or board (a faulty or badly seated Mega did exactly this on the bench).
Joystick (HID) interface
Overhead and console switches reach the simulator as ordinary USB joystick buttons. The upper controller scans the switches and sends each change over UDP to a small USB board, UDP_TO_HID, which Windows sees as four joysticks and a keyboard.

How a switch becomes a joystick button
The upper controller numbers each matrix position as index = row × 11 + column (0–175).When a switch changes, it sends index,state to 172.16.1.11:4210, with state 1 = switch on and 0 = off.The HID board picks joystick = index ÷ 32 and button = index mod 32, then holds that button down while the switch is on.Keypad keys are sent as KEY,<key>,<state> and typed as keyboard keys 0–9, * and #.The servo board sends the same index,state format for its three front-panel switches: index 7 (warning mute, pin 47), 8 (TOT clear, pin 43) and 9 (fuel valve, pin 48), with 1 = closed.

Setting FSUIPC events from the joystick buttons
A joystick button does nothing in the simulator until it is bound to an event in FSUIPC. The Warning Mute and Fuel Valve switches on the servo board must be set this way before they work; the TOT clear switch beside them is bound the same way. This applies to P3D and FSX with FSUIPC and DODSIM206V2.EVT installed (see Installing the DodoSim event file above). In MSFS, bind the buttons in the controls menu instead; the DS206 events are not available there.
1. Start the simulator with the USB HID board connected. Windows should list the four joysticks (Game Controllers, joy.cpl); pressing a switch lights the matching button there.
2. In the simulator open FSUIPC from the Add-ons menu and choose the Buttons + Switches tab.
3. Operate the switch you want to bind (for example flip the Fuel Valve switch). FSUIPC shows the joystick letter and button number it saw. Note that FSUIPC counts buttons from 0 and Windows from 1, so Windows button 10 shows as button 9 in FSUIPC.
4. Under the pressed (or closed) side, tick Select for FS control, choose the event from the list and type the parameter in the box beside it. The DS206 events are listed alphabetically.
5. A switch that stays on needs the released side set as well: tick Select for FS control there, choose the same event and enter the opposite parameter, so the cockpit follows the switch in both directions.
6. Click OK, flip the switch and check the result in the cockpit. FSUIPC keeps the assignment in its settings file, but after an event file update it re-indexes the events alphabetically, so check these bindings again.
Warning Mute: Joystick 1 button 8 (FSUIPC button 7). Event DS206.WARNING_MUTE_BUTTON_SET, parameter 1 when pressed and 0 when released. Alternatively bind DS206.WARNING_MUTE_BUTTON_TRIGGER (no parameter) to the pressed side only.
Fuel Valve: Joystick 1 button 10 (FSUIPC button 9). Event DS206.FUEL_VALVE_SWITCH_SET, parameter 1 when closed and 0 when released. The valve in the simulator follows the switch; if it ends up the wrong way round, swap the two parameters.
TOT clear (TOT light test): Joystick 1 button 9 (FSUIPC button 8). Event DS206.TOT_TEST_BUTTON_SET, parameter 1 when pressed and 0 when released.
If FSUIPC does not see a switch, check that Windows shows the button moving in joy.cpl first. If it does not, the problem is on the board side (the servo board's debug messages report each change and the HID board logs the button it sets).
Bell_206_Switch_Mappingsv1d.xlsx also plans a Leo Bodnar USB board for COM/NAV, autopilot, ADF and a hat switch; no firmware for it is in the repo.
Known issues
The HID board's own test button on pin 5 also drives Joystick 1 button 1, the same button as HTR 0.CreateDcsBiosMessage() is still a stub, so these switches do nothing in DCS; only the joystick path works.The Health Monitor shows the HID board as JoyStick and the upper controller as Upper Input.The HID board also reboots when it receives C,RESET:1 (or RESET) on UDP 4210. Its USB connection drops while it restarts, so Windows briefly loses the four joysticks and the keyboard and then detects them again; re-check any game that has them open.The servo board's three switches use index 7, 8 and 9, which Windows shows as Joystick 1 buttons 8, 9 and 10. If they were meant to be Windows buttons 7, 8 and 9, button 7 is already the Air heat switch (index 6), so the indexes would have to move.

Calibration
The servo board turns attitude degrees into a servo position (0–180) with two small tables in the sketch. Between table points it interpolates in a straight line; beyond the ends it holds the end value. The stepper gauges have their own step tables, described in their sections.
InstrumentAttitudeServo positionPitch (PITCH_DEG_TABLE)−30°179Pitch0° (level)113Pitch+30°70Bank (BANK_DEG_TABLE)−90°5Bank0° (level)93Bank+90°179
The self-test sweep uses aServMinPosition[] and aServMaxPosition[] (bank 5–179, pitch 166–70) and parks at aServZeroPosition[] (bank 93, pitch 113).
Calibrating a servo
Send raw positions with BANKRAW or PITCHRAW (for example D,PITCHRAW:113), or use the ServoTuner app, until the instrument shows a known attitude.Note the position for each attitude you check: at least both ends and level.Enter them in PITCH_DEG_TABLE or BANK_DEG_TABLE, and set aServZeroPosition[] to the level position so the self-test parks there.Upload, then check with real values, for example D,PITCH:0 and D,BANK:30.
Do not drive a servo hard against its mechanical stop. A stalled servo draws high current and gets hot.

Known issues in the code
Firmware (JET_RANGER_SERVO_CONTROLLER.ino)
Brightness packets (C,B:n) are accepted but do nothing: no pin is assigned and the PWM line is commented out. The PCB has BACKLIGHT_PWM on pin 5 ready for it.powerAvailable is set from NAVCOM1 but nothing uses it, so the attitude indicator and lamps stay live when the sim's power is off.Several annunciators log Transmission Temperature changed to the debug listener, whichever lamp changed.The #define comments for pins 26 and 27 still say "Using Gas Producer Port" and "Using Radar Alt Port" from the old servo layout.The PCB labels 10 of the 15 annunciator outputs on different pins from the sketch (A1/A2, A5/A6, A7–A10, A11/A12). Test each lamp on its own, for example D,RLOW:1, and correct whichever side is wrong.
FSUIPC event file (DODSIM206V2.EVT)
Line before event 133 is missing its //, so FSUIPC may reject or mis-read it.Events 189 and 190 are named the wrong way round: 189 is called _SET but toggles, 190 is called _TOGGLE but takes 1 or 2.Events 69–71 mix up the instrument and cockpit light breakers: 69 is named COCKPIT_LT_CB_TOGGLE, and INST_LT_CB_SET appears twice.
